## Session 2026-11-07 (suite 3) — Space : les cases debordaient sur la barre Hall/SAVE (`a5007f01`)

Symptome : « la longueur verticale des cases debordent sur les cases Hall save ».

**Cause** : les cases descendaient jusqu'à **y=353,5 dp** (fenêtre de 392) alors que
la pastille du preset et SAVE commencent vers **y=337 dp**. Le `Row` du pied est en
`Alignment.BottomEnd` : il ne réserve PAS de bande, il flotte. Rien ne borne la
hauteur des cases.

**Correctif** (`AeSpaceScreen.kt`) :
- rangée remontée : `offset(y = 100.dp)` -> **88 dp** ;
- interne resserré : `padding(top = 10, bottom = 12)` -> **6/6**, `spacedBy(8)` -> **5**.

**Mesure après** : cases de **91,5 à 326 dp**, pastille Hall à **~350 dp** ->
**24 dp d'écart**. Les knobs de case restent à **48 dp** visibles (inchangés).

**Méthode de mesure** : le repère n'est pas l'échelle 2,7497 seule — la fenêtre
Space (860x392) est centrée dans un écran 891x411, donc **offset (+15,5, +9,5) dp**
entre coordonnées image et coordonnées fenêtre. Les lignes de cadre se détectent par
`(row > 70).mean() > 0.55` sur la largeur de la rangée : ça sort le haut et le bas
des cases sans ambiguïté, alors que la boîte englobante d'un mot OCR, non.

## Suite — T6 clos : test de bout en bout + branche poussee

**Le test manquant** (`BootSetlistRestoreTest`, 2 cas) monte le boot complet : une
setlist sur disque, la preference d'etat posee, puis un **second** `MixerViewModel`
comme au relancement. Il verifie que la setlist **et son patch actif** reviennent
(c'est le patch qui porte le rack FX), et qu'une setlist supprimee n'est pas rouverte.

**Pieges du banc (chacun a coute une passe) :**
1. `loadAppState()` renvoie `null` sans `bpm` **et** `tracks_json` : un etat seede
   minimal doit poser ces deux cles, sinon la restauration ne tourne jamais.
2. `openProject()` finit par un `withContext(Dispatchers.Main)` : sous Robolectric un
   `Thread.sleep` ne pompe pas le looper principal, donc la reouverture reste en
   attente. Il faut `ShadowLooper.idleMainLooper()` dans la boucle d'attente.
   Sans ca : `scenes=[BootShow]` mais `activeProjectName=""`.

**Regle** : un test de boot qui traverse un `withContext(Main)` doit pomper le
looper ; sinon il echoue pour une raison qui n'a rien a voir avec le code teste.

**Nettoyage** : `hasActive`/`restoredProjectName` etaient devenus des constantes
(`false`/`""`) apres le passage a `pendingSetlistRestore` — supprimes, les champs
`activeSceneId`/`activeProjectName` sont poses vides au restore (c'est
`restoreLastOpenedSetlist` qui les remplit).
