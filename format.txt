1.2 — Comment est appliqué le facteur scale aujourd'hui ?

              y = (cy * s).dp - diameter / 2f,

      box.x / box.h sont-ils multipliés par scale ? Réponse : OUI, indirectement.
      cx et cy sont calculés DANS l'échelle de référence puis multipliés :
          val cx = box.x + box.w / 2f      (l.111)
          val cy = box.y + box.h / 2f      (l.112)

      ≈ scale-de-référence, les knobs sont énormes et le panneau ne mesure pas

5.1 — Les knobs font ×3 à ×5 leur taille cible :
      CONFIRMÉ PAR LE CODE — OUI.
      Cause : FxOpenPanel.kt:113 : diameter = (box.w * 0.86f * s).dp, où
      `s = scale` (l.63) et le seul appelant passe scale = 1f
      (FxWindowCaptureTest.kt:57). Or box.w est une largeur de boîte MESURÉE
      dans la référence 825×343 (ex. Solar Ceiling « Amount » : w = 138.1,
      FxGeometry.kt:53). Multipliée par 0.86 × 1 → 118.8 dp de diamètre pour
      un écran qui n'est pas à l'échelle de 825 dp de large. Donc les knobs
      sont dessinés à leur taille « pleine » de référence sur un panneau qui,
      lui, est en fillMaxSize(). D'où l'impression de ×3 à ×5.

5.2 — Le rack reste visible derrière le panneau ouvert :
      CONFIRMÉ PAR LE CODE — OUI.
      Cause : FxWindowHost.kt:59-86 — la Column « Header + Rack » n'est jamais
      retirée ; FxOpenPanel est posé PAR-DESSUS avec Modifier.fillMaxSize().
      Il n'y a aucune logique XOR. Voir 1.1.

5.3 — Le fond spécifique de l'effet (beige pour Solar Ceiling) est absent :
      CONFIRMÉ PAR LE CODE — OUI.
      Cause : le seul fond dessiné est GÉNÉRIQUE (FxScenes.kt:173, dégradé
      #171C28 → #0B0E16) et identique pour tous les effets. Aucun dégradé
      beige/brun/violet par effet n'existe. Voir 1.5.

5.4 — Le header est éclaté, pas dans un bandeau de 42 px en haut du panneau :
      CONFIRMÉ PAR LE CODE — OUI (deux bandeaux concurrents, deux valeurs).
      Cause : le panneau utilise un header de 58 dp
      (FxOpenPanel.kt:85 : .height((58 * s).dp), avec padding start 58 / end 200
      l.86), alors que la coque WindowHost utilise un header de 42 dp
      (FxWindowHost.kt:123 : .height((42 * s).dp)). Les deux sont dessinés en
      même temps (l'un sous l'autre car le panneau recouvre), et la valeur 58
      n'est pas multipliée par une échelle réelle (s = 1f). Le titre 30 sp
      (FxOpenPanel.kt:91) et le chip preset en position absolue (l.78) ne sont
      donc pas alignés sur un bandeau de 42 px.

5.5 — Le bottom bar LEVEL est mal positionné (pas à y = 214 du panneau) :
      CONFIRMÉ PAR LE CODE — OUI, et pire : la barre n'est JAMAIS posée.
      Cause : FxGeom.BOTTOM_BAR_Y = 214 et LEVEL_X/Y/W existent
      (FxGeometry.kt:9-13) mais ne sont utilisés NULLE PART dans la coque.
      Recherche faite : hors de FxGeometry.kt, aucune référence à
      BOTTOM_BAR_Y / LEVEL_X / LEVEL_Y / BOTTOM_BAR_H. FxBottomBar.kt ne
      contient qu'un facteur dB (l.13). La seule vraie barre posée est dans
      l'ANCIENNE fenêtre : FxWindow.kt:194 → drawFxRail(...). Donc dans la
      coque, il n'y a pas de LEVEL à y = 214 : il n'y en a pas du tout.

5.6 — La scène animée (courbes jaunes) n'est pas dessinée dans le panel :
      NON CONFIRMABLE PAR LE CODE — le code APPELLE bien la scène.
      Fait : FxOpenPanel.kt:68-70 dessine un Canvas fillMaxSize() et appelle
      `with(module) { drawScene(params, clock.value, mini = false, tm) }`,
      qui route vers sceneCeil pour l'id 4. La scène EST appelée. Si elle
      n'apparaît pas, la cause probable est le GEOMETRIE : la scène se peint
